# Changelog

## 1.9.0 - 2026-11-05

- Right-click a file of the working tree changes and choose **Revert...** to throw away its uncommitted change, after confirming: a file in **Changes** goes back to its staged version, keeping its staged changes, and one in **Staged Changes** goes back to the last commit. A new file, or a rename's new name, leaves the index and stays on disk, untracked (a rename's old name comes back). Untracked files, renames that only change the case of a name, and staged files while **Amend Last Commit** is ticked have no **Revert...**.
- Right-click a changed file and choose **Open With...** to pick what opens it. In VS Code, it lists the editors that can open the file. In the standalone app, Windows shows its own "How do you want to open this file?" dialog, and macOS lists the applications that open the file, with **Other Application...** to choose any other. Not in the standalone app on Linux.
- A repository opens showing just the checked out branch (every branch while HEAD is detached). Before, it showed every branch. **Display Checked Out Branch on Open** in the **View** menu below the graph is now on by default; turn it off to open with every branch again. A repository where you had turned it off keeps it off.
- Ctrl+Click (Cmd+Click on macOS) the changed files in a commit's details or the commit form to select several, then right-click one and choose **View Diff of N Files** to open their diffs together: in VS Code's multi-file diff editor (a tab each in VS Code versions without it), or in the standalone app's diff tool as a comparison of folders holding just those files. Ctrl+Click a selected file again to unselect it, or click a file plainly to unselect them all; selected files the file filter hides are left out until they show again. A file partly staged, selected in both of the commit form's lists, opens once, and in the standalone app double-clicking one of the selected files opens them all.
- **Standalone app**: opening the diff of an untracked file opens the file itself, as VS Code does, since it has nothing to compare with. Before, the diff tool showed nothing and no message said why.
- **Standalone app**: the diff of a file whose name holds `[`, `*` or `?`, such as `pages/[id].tsx`, compares just that file. Before, `git difftool` read the name as a pattern and compared the files it matched too, such as `pages/i.tsx`.
- Deleting a branch the graph shows, outside Sidereal, could show "Unable to Load Commits (fatal: bad revision ...)" when it happened while the graph refreshed. The graph now loads again without the branch.
- Drag the commit details view by its title bar onto the right or the bottom of the commit list to dock it there (an outline shows where; Escape cancels), or choose **Dock Details Right**, **Dock Details Bottom** or **Dock Details by Window Shape** in **View** or the title bar's right-click menu. Sidereal remembers the side across restarts and in every tab, except where the window is too small for it, such as a short VS Code panel or a narrow sidebar. By window shape, as before, it docks on the right while the window is wider than tall and at the bottom otherwise.
- Docked below the commit list in a window at least 520 pixels wide, the commit details view shows its **Details** section and its changed files side by side at the view's full height, sharing the width by the divider between them. Side by side, the sections don't collapse; docked on the right, or in a narrower window, they sit one above the other and collapse as before.
- **Standalone app**: Beyond Compare, WinMerge, KDiff3, Meld and P4Merge open a file's diff directly, as TortoiseGit does, without the start-up script of `git difftool`, which is slow on Windows. A file's versions at commits open as read-only copies, and the working tree's file stays editable. A file without changes now opens too; folder comparisons, submodules and a command set in Git's config (`difftool.<tool>.cmd`) still go through `git difftool`.
- **Standalone app**: right-click a tab and choose **Rename...** to give it a name of its own, or press F2 with the keyboard focus on the tab strip. Enter or a click elsewhere keeps the name, Escape cancels, and a blank name gives the tab back its folder name. The name shows in the window's title and the **Window** menu, stays when the tab opens another repository, and lasts across restarts until the tab is closed.

## 1.8.1 - 2026-11-04

- In a VS Code window that updated Sidereal from 1.7 without reloading, choosing a style in **Label Colors...** failed with "not a registered configuration": the window didn't know the new label settings yet. The dialog now waits for a reload before opening by itself, and choosing a style offers **Reload Window** instead of failing.
- In VS Code themes that don't color the edges of text fields (such as Light+ and Dark+), the commit form's summary and description, **Filter messages** and Sidereal's other text fields have a border, in the color of the dropdowns' border. Before, they had none, and on a background of their own color they couldn't be seen.

## 1.8.0 - 2026-11-04

- Ticking **Amend Last Commit** in the commit form lists the last commit's changes under **Staged Changes** together with the staged ones, as the amended commit will have them. Unstaging a file there leaves it out of the amended commit, keeping its change in the working tree, and its diff compares with the commit before the last. It also fills in the last commit's message when you had typed a message already, and unticking it brings back what you had typed. Before, it filled in the message only into empty fields, and the list showed only the staged changes.
- **Standalone app**: the AI Features settings that show the AI buttons are now named **Resolve Conflicts with AI** and **Generate Commit Message with AI** (they began with "Offer").
- The settings that choose the AI agent and its custom command, which Resolve with AI and Write with AI share, are now `sidereal.ai.agent` and `sidereal.ai.command` (they were `sidereal.conflicts.aiAgent` and `sidereal.conflicts.aiCommand`). Sidereal moves what you set under the old names to the new names when it starts.
- **Write with AI** (the sparkle beside the commit form's summary) writes the commit message of the staged changes with Claude Code, Codex or GitHub Copilot CLI, whichever you have installed, and fills in the summary and description for you to edit. It runs the agent read-only, telling it the staged changes and the last commits' messages, so the message follows the repository's style, and it builds on what you have typed. With **Amend Last Commit** ticked, the message covers the last commit's changes and the staged ones. It uses the agent chosen in Settings, or asks which one when several are installed. The progress notification can stop it. Settings shows each agent's Write with AI command beside its Resolve with AI one, and `sidereal.commitForm.writeWithAI` hides the button. A custom AI command can't be held to read-only: Write with AI only asks it not to change files, and Settings says so. A reply that introduces the message ("Here is the commit message:") without the lines Sidereal asks for is no longer taken for part of it.
- While nothing is staged, the commit form says so below **Commit** and **Commit & Push**, with the **Stage All** button of its Changes list (**Stage Shown** while the file filter hides some, staging only the files it shows). Pressing **Commit** or **Commit & Push** when it can't act now shows why: it flashes that message, which screen readers announce, or the reason it can't act (such as no checked-out branch to push), or focuses the summary when it is empty. Before, the button only looked faded, the reason was in its tooltip, and pressing it seemed to do nothing.
- A button that can't act says why when pressed, in a message, as an unavailable menu item already did: **Continue**, **Commit...** and **Resolve with AI...** in the operation banner, **Rebase**, **Cherry Pick** and **Revert** in the banner of a plan, and the buttons of **Manage Branches** and **Manage Tags**. Before, pressing one did nothing.
- **Commit...** on the working tree changes row shows the details view's **Details** section expanded even when you collapsed it, so the commit form shows with its summary focused. Before, the form stayed hidden and nothing seemed to happen. Details stays collapsed for the other commits.
- Clicking a branch, tag or stash label in the graph opens its commit's details, as clicking the rest of the row does. Before, it did nothing. While a menu is open, clicking a label still only closes the menu.
- In the **Branches** dropdown, clicking a branch shows just that branch and closes the dropdown. Ctrl+Click (Cmd+Click on macOS) adds or removes a branch and keeps the dropdown open, to show several. Ctrl+Double-Click (Cmd+Double-Click) on **Show All** ticks every branch, so you can then Ctrl+Click (Cmd+Click) the ones to leave out. The options' tooltips say so.
- The **Branches** dropdown lists the branches you selected first, below **Show All** and **Current Branch**, with a line under them, so you no longer scroll through every branch to find them. The order is set as the dropdown opens and stays put while you Ctrl+Click (Cmd+Click) more, even when the branches refresh, so no branch moves under the pointer. Typing in its filter lists the matches in the usual order.
- Selecting several commits with Ctrl+Click (Cmd+Click on macOS), Alt+Click, Shift+Click or Shift+Up / Down keeps the details view open, showing the commit you selected last, outlined among the selected rows. Deselecting the commit it shows shows the one selected before it. While commits are selected, Up / Down don't move the details view (which would end the selection), and Ctrl+Up / Down still push and pull; press Escape to end the selection first. Before, selecting a second commit closed the details view.
- Double-clicking an option in the **Repo** or **Branches** dropdown no longer also clicks whatever was under the dropdown, such as a commit, opening its details.
- The changed files in a commit's details can be shown as a tree of folders: the button at the right of the file list's header switches between the list and the tree, and Sidereal remembers which you chose. Click a folder to collapse or expand it. A folder that holds nothing but another folder shares its row with it (`docs/architecture`). The commit form's staged and unstaged changes follow the same choice.
- In the list view, a header row above the changed files sorts them: click **Name**, **Added** or **Removed** to sort by file name or by lines added or removed, again for the other way round, and a third time for the folder order again. Sidereal remembers the order.
- A **Filter files** field above the changed files shows only those whose path contains every word you type, ignoring case, in the list or the tree, with how many match. A renamed file matches by its old path too. In the tree, every folder holding a match shows expanded while you filter. In the commit form, **Stage All** and **Unstage All** act on the files the filter shows, and read **Stage Shown** and **Unstage Shown** while it hides some. The filter stays as you open other commits, until the details close; Escape or its **×** empties it.
- A file's buttons in the commit details (copy its path, open it, stage it...) show only while the pointer is on its row, leaving its name the room the whole time.
- The controls above the graph (**Repo**, **Branches**, the filter field, **Jump** and the buttons beside them), the summary of an applied filter and the banner of an operation stay at the top as you scroll, with the header row below them. Before, only the header row stayed in view, and the controls scrolled away.
- With **Compressed Graph** on, Sidereal reads the commits' parents with one Git command instead of one per 100 commits, and **Copy Messages to Clipboard** runs one Git command for any number of commits. Sidereal also starts at most 8 Git commands at once, so a burst of refreshes no longer starts dozens together.
- The References view reloads only the repositories whose Git files changed when you commit, fetch or switch branches, instead of every expanded repository.
- Hiding or showing the **Actions** column or the local branch labels, **Collapse Runs of Commits**, and how the commit details show their sections and changed files (as a list or a tree, and in which order) now take effect at once in every other open Sidereal tab and view. Before, the others kept their old layout until they reloaded, and another tab's **Actions** column showed empty cells as you scrolled.
- **Standalone app**: on Windows, a repository on a mapped network drive keeps its drive letter, and repository paths are spelled as in Sidereal for VS Code (with a lower-case drive letter) whichever way the repository was opened.
- In histories of tens of thousands of commits, the graph previews a drop, and a rebase, cherry pick or revert being planned, a little faster.
- **Standalone app**: a repository on a network drive that stopped answering no longer freezes the app while Sidereal checks whether its folder is still there, or lists the repositories you opened.
- The **Branches** dropdown stays quick with thousands of branches: it shows only the branches in view as you scroll or type in its filter, and picking a branch no longer redraws the whole list.
- **Manage Branches** and **Manage Tags** stay quick with thousands of branches or tags: typing in their filter, sorting and selecting no longer redraw every row.
- In the References view, the prompts of the remote actions (**Add Remote...**, **Edit Remote...** and **Fetch from Remote with Options...**) work like Sidereal's other prompts: they wait for a Git password prompt that is open instead of closing it, the last question of **Add Remote...** stays open when you click elsewhere, as its earlier ones do, and typing in the fetch options also matches their Git flags.
- **Standalone app**: a tab you close no longer opens again at a later start when its repository's drive wasn't mounted as the app started.
- **Pull**, **Push**, **Commit** and **Stash** buttons next to the Branches dropdown, as in Git Extensions. **Commit** shows how many files changed and opens the commit form. The arrow beside **Pull** offers **Pull...**, **Pull - merge**, **Pull - rebase**, **Fetch**, **Fetch all** and **Fetch and prune all**; tick **Set default Pull button action**, then choose one, to make it what the button does. The arrow beside **Stash** adds **Stash Pop...** for the latest stash.
- Git Extensions' shortcuts: Ctrl+Space commits, Ctrl+Up pushes, Ctrl+Down presses the Pull button, Ctrl+Shift+Down fetches, and Ctrl/Cmd+Alt+Up / Down stash and pop the latest stash. While a commit's details are open, Ctrl/Cmd+Up / Down still move to its child or parent. On macOS, Cmd+Up / Down still scroll to the top and bottom of the graph, and Ctrl+Up / Down push and pull once Mission Control's shortcuts for them are turned off.
- **Label Colors...** in the View menu below the graph colors the branch, tag and stash labels as another Git tool does: TortoiseGit (the default), Git Extensions, JetBrains, GitKraken / GitLens, Fork / Sourcetree, Git Graph or VS Code, or in colors of your own. Each style shows sample labels, and the graph behind the dialog takes the one chosen. The dialog opens by itself the first time the graph shows a repository. The setting is **Sidereal › Reference Labels: Style** (in the standalone app, **Settings > Appearance > Label colors**); a choice made in the dialog is saved in the workspace settings when they set it.
- A stash's **Delete Ref...** is now **Drop Stash...**, and **Combine to one commit...** is **Combine to one commit (squash)...**.
- A Sidereal tab that VS Code reopens after a restart shows the repository it is titled after, even when its graph never loaded before VS Code closed. Before, it showed the repository you viewed last, sometimes the same one as another tab.

## 1.7.0 - 2026-11-02

- **Resolve with AI...** in the conflict banner and on each conflicted file hands the conflicts to Claude Code, Codex or GitHub Copilot CLI, whichever you have installed. The agent resolves every conflict, saying which way it went where the two sides clash, and Sidereal marks each file as resolved. For a rebase, or a cherry pick or revert of several commits, it can carry on to the end: it continues after each commit and resolves the next one's conflicts the same way, stopping at any it leaves unresolved. It then says how it went and what is left to do, with what it did in each commit and what the agent said collapsed below. Files both sides deleted are marked as resolved without the agent. A merge's commit stays yours. If the custom AI command in Settings can't run, the dialog says why. Everything is asked and reported in Sidereal's own dialogs, and **Next time, start without asking** skips the question (`sidereal.conflicts.confirmResolveWithAI`, `sidereal.conflicts.aiAgent`). `sidereal.conflicts.resolveWithAI` hides it.
- When a merge, rebase, cherry pick, revert, pull, or an applied stash or patch stops on conflicts, the graph says so in plain words, with **Resolve with AI** (and a choice of agent) and **Resolve Myself**, instead of showing Git's output as an error. With **Always resolve with AI without asking** on, the agent starts right away.
- Settings has an **AI Features** section (**Sidereal › AI** in VS Code) that shows the command each agent runs. Choose **Other** to run a command of your own, with `{prompt}` where the prompt goes, for example `aider --yes --message {prompt}`. These are user settings only, so a repository's workspace settings can't choose what runs.
- **Drag and drop in the graph**: drag a branch label onto another commit or branch to rebase it there, even a branch that isn't checked out, or onto the checked-out branch to merge it. Drag commits (or a selection) onto the checked-out branch to cherry-pick them. Each drop opens a menu of what it can do; a merge's dialog confirms, and a rebase or cherry pick is planned in the graph. Resting on a target previews the result in the graph, with the commits being moved highlighted and collapsed runs kept collapsed, and every change is animated.
- **Delete Worktree Folder...** in the graph's menu for another worktree's branch deletes that worktree after confirming. It stops instead while the worktree has uncommitted changes or untracked files.
- **Standalone app**: Show Log and Fetch in the file manager's right-click menu, as in TortoiseGit. Show Log on a file or folder shows its history.
- **Standalone app**: the **+** button (and **File > New Tab**) opens a New Tab dialog with your favorite and recent repositories. Type to filter, pin a repository to keep it in Favorites, or choose **Open Folder...** for any other.
- **Standalone app**: on Windows, the tab strip is the window's title bar, as on macOS, instead of sitting below a title bar and a menu bar. The window's buttons sit at its right end in the app's light or dark colors, and the menu opens from the button at its left, or with Alt or F10.
- **Standalone app**: after a few days of use, Sidereal asks once whether you'd star it on GitHub. **Help > Sidereal on GitHub** opens the repository, and after an update to a new minor version a message links to its release notes. The **About** section of Settings links to Sidereal's website, its repository, its Marketplace and Open VSX pages, the changelog and the new issue page.
- **Report an Issue** in the message asking for a rating, and in the standalone app's **Help** menu, opens the new issue page, as the command does, instead of the list of issues.
- The filter button opens the filter options in a panel over the graph, like the standalone app's Settings, instead of a bar above it. **Apply** and **Clear** close it.
- **Standalone app**: prompts, such as a new branch's name, have a close button that cancels them, like Escape. A list of choices shows its question above it instead of in a filter field, which only long lists of single choices have now.
- **Merge** asks in one dialog that lists the commits it brings in, with its options below them, instead of a series of prompts, in VS Code as in the standalone app. It shows whether it can fast-forward, and keeps **Don't commit** and the strategy options under **Advanced**. An option that doesn't apply with the others is turned off, its reason in its tooltip, and the dialog stays open while the view refreshes in the background.
- Every rebase is planned in the graph instead of a dialog: the graph shows the commits it replays where they will go, newest at the top, and a **Rebase** column slides out beside it with each commit's handle and action. They start all picked, ready to run as they are, or to drag into another order, reword, edit, squash, fix up or drop first (or press P, R, E, S, F or D), and the graph shows each change at once: a dropped or squashed commit loses its dot. A reworded or squashed commit's message is edited below its row. The banner above the graph, which stays in view as you scroll, says what the rebase does and holds **Change All to...**, **Rebase** and **Cancel**; Enter rebases and Escape cancels. It replaces the separate **Interactive Rebase** choice, and rebases a branch that isn't checked out too. **Ignore Date** is gone.
- While a rebase is under way, the graph keeps showing its commits the way it planned them, in the **Rebase** column: the commits made so far with a check, the one it stopped at (marked when on conflicts), and copies of those still to come on top. A step that made no commit of its own (skipped, or left with nothing to change) is named on the commit before it, and commits you make yourself at a stop, such as a commit split in two, stay in the band with that step. The banner shows how far it has got. For a cherry pick or revert of several commits, the banner lists those left. **Continue** (or **Resolve with AI...** while conflicts remain) stands out as the next step.
- **Cherry Pick** and **Revert** are planned in the graph instead of a dialog: the graph shows the commits they will add on top of the checked-out branch, and the banner above it, which stays in view as you scroll, says what they do and holds their options (**Record where it came from**, **Don't commit**, and for a merge commit the parent to apply it relative to) with **Cherry Pick** or **Revert** and **Cancel**. Enter starts it and Escape cancels. With **Don't commit**, the graph highlights the commits it applies instead. When the graph doesn't show the checked-out commit, the banner lists the commits.
- The buttons of the graph's dialogs can be reached with Tab and pressed with Enter or Space. In the merge dialog and the conflict overlay, Tab stays inside the dialog.
- The graph's SHA-1 column shows the first 8 characters of each hash instead of the full hash. Hover a hash to see it in full.
- **Standalone app**: releases no longer include the macOS and Windows zips. Download the `.dmg`, the `Sidereal-Setup` installer or the `.AppImage`.
- A rebase stopped on conflicts in a squash or fixup no longer says it stopped to edit the commit, and **Skip** asks about skipping the commit rather than its editing.
- A rebase whose plan was changed now drops a commit left with nothing to change, as one run as planned does, instead of stopping there. When the plan edits a commit, or squashes or fixes up commits, such a commit is kept (empty) instead, so the edit or the squash still applies to it rather than to the commit before it.
- When Sidereal fails unexpectedly while committing, merging, rebasing or cherry picking, the commit form's buttons work again afterwards, a dropped commit or branch no longer leaves its preview in the graph, and the Actions column keeps filling in as you scroll.
- A file's **Uncommitted** diff opened again after a commit compares with the new HEAD instead of the HEAD it was first opened with, and a conflict's **Ours ↔ Theirs** diff shows the current conflict's sides, not an earlier one's.
- A rebase being planned stays when a fetch in the background (VS Code's autofetch, a terminal) adds or prunes remote branches, or the graph refreshes, instead of losing the plan. It is cancelled when the checked-out branch or the local branches change.
- After `git submodule deinit` (or deleting a nested repository's `.git`), the folder left behind no longer hands its view state, such as its name, columns and issue linking, to the repository it is in, overwriting that one's.
- **Standalone app**: on Linux, **Open in Terminal** works without `x-terminal-emulator` (which only Debian and Ubuntu have): it tries `$TERMINAL`, then GNOME's, KDE's, Xfce's and other terminals, and xterm.
- **Standalone app**: tabs of repositories on a drive that isn't mounted when the app starts are no longer forgotten. They open again at a later start, once the drive is back.
- **Standalone app**: on Windows, a repository opened from **File > Open Repository** or by dropping its folder no longer opens a second tab when it is opened again another way, such as **Show Log** in Explorer, and is listed once in **Open Recent** and the New Tab dialog.
- **Standalone app**: binary files in a commit's details no longer show "+NaN −NaN" (and NaN in the totals), and no longer offer a diff that can't be shown.
- In VS Code, the graph picks up changes made outside VS Code as the standalone app does: Git commands run in a terminal, such as `git add` marking a conflict resolved, creating a branch or a tag or dropping a stash, and files changed by other programs. It no longer waits until you switch back to VS Code's window or press F5, and keeps refreshing in a repository with more than 10,000 changes.
- A change made right after another, such as a second `git add` a second after the first while the graph was still refreshing, or right after one of Sidereal's own actions, is no longer missed, leaving the graph showing a conflict already resolved.
- The graph no longer reloads after an install or a build writes more than 10,000 files into a folder Git ignores, such as `node_modules`.
- In a text field, such as the commit form's summary, Escape leaves the field instead of closing the commit details, and on macOS Ctrl+H deletes the character before the caret instead of jumping to HEAD.
- Switching repositories while the **Working tree changes** were loading no longer shows the previous repository's changes in the new one's details, where staging or committing would act on the wrong files.
- A commit that changes a file in a folder named `constructor`, `toString` or the like no longer leaves its details stuck on "Retrieving Commit Details ...". A branch of such a name no longer always counts as selected in **Manage Branches** (and so deleted with the selected ones), nor shows a worktree or upstream badge it doesn't have.
- Checking out a branch that was deleted meanwhile (in a terminal, say) no longer checks out the files of a folder of the same name instead, throwing away their uncommitted changes. It fails, saying the branch is gone.
- **Commit & Push** pushes to the branch's upstream only where `git push` would: a branch made from `origin/main` under another name no longer pushes its commits onto `main`, and a branch that pushes to another remote (`branch.<name>.pushRemote`, `remote.pushDefault`) no longer pushes to the one it fetches from. Sidereal asks where to push instead.
- A checked-out branch with a tag of the same name (a branch `v1` and a tag `v1`) is shown as checked out again in the References view, and named `v1` instead of `heads/v1` when an action stops on conflicts.
- Fetching a remote branch into a local branch, and pulling a remote branch, no longer take a tag of the same name on the remote instead (which left the branch's new commits unmerged and said "Already up to date").
- Deleting a branch on a remote no longer also deletes a tag of the same name there (or only the tag, once the branch is gone from the remote), and deleting a tag on a remote no longer deletes a branch of the same name.
- **Edit Remote...** no longer fails with "No such URL found" when the old URL has a character such as `+` or `?` in it, and removing a push URL no longer also removes the others that contain it.
- The **Sidereal** output log masks passwords and tokens in URLs, such as a remote's `https://user:token@host/repo.git`, so the log is safe to share in an issue.
- Sidereal uses the Git executable that `git.path` names after a restart too, instead of the one it used last, and switches to the one it finds itself once `git.path` is cleared.
- **Reset** (to a commit, or of the uncommitted changes) no longer starts on **Hard** because it was chosen last time, so one Enter can't throw away the uncommitted changes. It starts on **Mixed** instead.
- A repository without commits, such as one just created with `git init`, shows "This repository has no commits yet." in the graph instead of an error with a **Retry** that couldn't work. Its first commit shows up on its own.
- On an orphan branch (`git switch --orphan`), whose first commit isn't made yet, the graph shows the other branches' history instead of "Unable to Load Commits: fatal: bad revision 'HEAD'".
- **Standalone app**: a crash or a full disk while the app saves no longer empties its `state.json` or `settings.json`, which lost every tab, recent repository and setting. A file that can't be read is kept as `state.json.corrupt` (or `settings.json.corrupt`) instead of being overwritten.
- **Standalone app**: when something fails while the app starts, it says so and quits, instead of staying open (or running without a window) and ignoring every later **Show Log**, **Fetch** and `sidereal` request.

## 1.5.0 - 2026-10-29

## 1.4.0 - 2026-10-28

- **Commit...** opens a commit form in Sidereal instead of git's `COMMIT_EDITMSG` file. It has a summary and description, staged and unstaged files you can stage or unstage one by one or all at once, **Amend Last Commit** and **Add Signed-off-by**, and **Commit** or **Commit & Push** (Ctrl/Cmd+Enter commits). A failing commit hook shows its output.
